# HSLog Game Rules

## 1. Overview

HSLog는 하스스톤 카드의 출시 시점을 비교하는 Higher or Lower 스타일의 웹 게임이다.

플레이어에게 두 장의 하스스톤 카드가 제시되며, 플레이어는 두 카드 중 어떤 카드가 더 먼저 출시되었는지 선택한다.

정답을 맞히면 다음 라운드가 진행되고, 오답을 선택하면 게임이 종료된다.

게임의 목표는 최대한 많은 카드를 연속으로 맞혀 높은 점수를 기록하는 것이다.

## 2. Core Gameplay

한 라운드는 두 장의 카드로 구성된다.

플레이어는 다음 질문에 답한다.

> 어떤 카드가 더 오래된 카드인가?

플레이어가 카드 중 하나를 선택하면 두 카드의 출시 시점이 공개된다.

### Correct

선택한 카드의 출시 시점이 상대 카드보다 빠른 경우 정답으로 판정한다.

### Incorrect

선택한 카드의 출시 시점이 상대 카드보다 늦은 경우 오답으로 판정한다.

### Result

- 정답: 점수를 1 증가시키고 다음 라운드로 진행한다.
- 오답: 게임을 종료하고 최종 결과를 표시한다.

## 3. Card Release Date

### 3.1 Definition

HSLog에서 카드의 나이를 판단하는 기준은 **최초 출시일(First Release Date)** 이다.

최초 출시일은 해당 카드가 Hearthstone에서 **처음으로 실제 플레이 가능한 상태가 된 날짜**를 의미한다.

카드의 최초 출시 이후 발생한 다음 이벤트는 최초 출시일을 변경하지 않는다.

- 카드 재출시
- Core Set 편입
- Standard 복귀
- Wild 이동
- 카드 밸런스 변경
- 카드 텍스트 변경
- 카드 능력 변경

예를 들어 2015년에 처음 출시된 카드가 2024년에 Core Set에 다시 포함되더라도 HSLog에서는 해당 카드를 2015년에 출시된 카드로 취급한다.

## 4. Determining the Release Date

HSLog의 카드 출시일은 카드 데이터의 `set` 필드를 기준으로 결정한다.

각 `set`은 해당 세트가 처음 출시된 날짜와 연결된다.

따라서 카드의 최초 출시일은 다음과 같은 관계로 결정한다.

Card → set → Set Release Date → First Release Date

### 4.1 Set-based Release Date

동일한 `set`에 속한 카드들은 기본적으로 동일한 최초 출시일을 가진다.

HSLog는 개별 카드의 출시일을 직접 관리하지 않고, 카드의 `set`과 세트 출시일 정보를 연결하여 최초 출시일을 결정한다.

### 4.2 Special Sets

다음과 같은 특수 세트는 일반적인 확장팩과 출시 구조가 다를 수 있다.

- Basic
- Classic
- Core
- Hall of Fame
- Adventure
- Mini-Set
- 기타 특수 세트

이러한 세트는 데이터 구축 단계에서 실제 최초 출시 시점을 확인하고 별도로 정의한다.

## 5. Round Structure

게임은 여러 개의 라운드로 구성된다.

첫 번째 라운드는 두 장의 카드를 무작위로 선택하여 시작한다.

정답을 맞힌 경우 이전 라운드에서 **플레이어가 선택한 카드 한 장을 다음 라운드에서도 유지**하고, 새로운 카드 한 장을 추가한다.

예를 들어 첫 번째 라운드에서 A와 B를 비교하고 A를 선택했다면 다음 라운드는 A와 C를 비교한다.

이후 C를 선택했다면 다음 라운드는 C와 D를 비교한다.

이 방식을 통해 매 라운드 완전히 새로운 두 장의 카드를 제시하지 않고, 이전 선택과 새로운 카드를 지속적으로 비교한다.

## 6. Card Selection

### 6.1 Initial Card

게임 시작 시 첫 번째 카드는 전체 카드 데이터에서 무작위로 선택한다.

단, 출시일 기준으로 극단적인 위치에 있는 카드는 첫 카드로 선택하지 않는다.

예를 들어 전체 카드 중 가장 오래된 카드와 가장 최신인 카드의 일정 비율을 제외한 영역에서 첫 카드를 선택한다.

초기 구현에서는 상위 및 하위 10%를 제외하는 것을 기본값으로 한다.

구체적인 제외 비율은 플레이 테스트를 통해 조정할 수 있다.

목적은 게임 시작부터 정답이 지나치게 명확해지는 것을 방지하는 것이다.

### 6.2 Next Card

다음 라운드에 추가되는 카드는 현재 유지되는 카드의 출시일을 기준으로 선택한다.

현재 카드보다 오래된 카드와 최신인 카드 모두 후보가 될 수 있다.

특정 방향으로만 카드가 선택되지 않도록 오래된 방향과 최신 방향을 모두 사용할 수 있어야 한다.

## 7. Difficulty

카드 간 출시일 차이가 작을수록 문제의 난이도가 높아진다.

예를 들어 2017년 8월 1일 카드와 2017년 8월 3일 카드를 비교하는 것은 2017년 8월 1일 카드와 2020년 1월 1일 카드를 비교하는 것보다 어렵다.

따라서 다음 카드는 현재 카드와 출시일이 가까운 카드를 우선적으로 선택한다.

단, 항상 가장 가까운 카드를 선택하지 않고 후보에 대한 가중치를 적용하여 랜덤하게 선택할 수 있다.

### 7.1 Difficulty Progression

게임 초반에는 비교적 쉬운 문제를 제공하고, 게임이 진행될수록 어려운 문제가 등장하도록 난이도를 점진적으로 증가시키는 것을 기본 방향으로 한다.

- Early Game: 상대적으로 큰 날짜 차이
- Mid Game: 중간 정도의 날짜 차이
- Late Game: 작은 날짜 차이

구체적인 난이도 가중치와 날짜 차이 기준은 플레이 테스트를 통해 조정한다.

난이도는 점수에 직접적인 영향을 주지 않는다.

모든 정답은 동일하게 1점을 획득한다.

## 8. Candidate Selection Rules

다음 카드 후보를 생성할 때 다음 조건을 만족해야 한다.

1. 현재 카드와 다른 카드여야 한다.
2. 현재 게임에서 이미 사용된 카드가 아니어야 한다.
3. 현재 카드와 출시일이 달라야 한다.
4. 현재 카드보다 오래된 카드 또는 최신 카드 중 하나여야 한다.
5. 현재 카드와 출시일 차이를 기준으로 난이도 조절이 가능해야 한다.

즉, 후보 카드는 다음 조건을 만족해야 한다.

- `candidate.id !== current.id`
- `candidate`가 현재 게임에서 사용된 카드가 아님
- `candidate.releaseDate !== current.releaseDate`

## 9. Same Release Date

동일한 출시일을 가진 두 카드는 하나의 라운드에서 비교하지 않는다.

동일한 확장팩에 속한 카드들은 기본적으로 동일한 출시일을 가지므로 서로 비교 대상이 될 수 없다.

이는 플레이어가 "어느 카드가 더 오래됐는가"라는 질문에 대해 논리적으로 유일한 정답을 선택할 수 있도록 하기 위함이다.

따라서 카드 후보를 생성할 때 현재 카드와 동일한 출시일을 가진 카드는 제외한다.

## 10. Used Cards

동일한 게임 내에서 이미 등장한 카드는 다시 선택하지 않는다.

예를 들어 다음과 같은 게임이 진행될 수 있다.

- Round 1: A vs B
- Round 2: A vs C
- Round 3: C vs D

이 경우 A, B, C, D는 모두 해당 게임에서 이미 사용된 카드이므로 이후 라운드에서 다시 등장하지 않는다.

이를 통해 긴 게임에서 동일한 카드가 반복적으로 등장하는 것을 방지한다.

## 11. Direction Balance

다음 카드가 현재 카드보다 오래된 카드인지 최신 카드인지는 특정 방향으로 고정하지 않는다.

두 방향 모두 게임에 등장할 수 있어야 한다.

따라서 플레이어가 단순히 특정 방향을 선택하는 전략만으로 게임을 진행할 수 없어야 한다.

## 12. Score

정답을 맞힐 때마다 점수가 1 증가한다.

정답을 맞히면 다음 라운드로 진행한다.

오답을 선택하면 게임이 종료된다.

최종 점수는 해당 게임에서 연속으로 맞힌 정답의 수와 같다.

예를 들어 4번의 정답 이후 5번째 라운드에서 오답을 선택했다면 최종 점수는 4점이다.

## 13. Streak

현재 연속 정답 수를 `streak`으로 관리한다.

정답을 맞히면 `streak`이 1 증가한다.

오답을 선택하면 게임이 종료된다.

MVP에서는 `score`와 `streak`을 동일한 값으로 취급한다.

향후 별도의 콤보 시스템이 추가될 경우 분리할 수 있다.

## 14. Game Over

다음 상황에서 게임이 종료된다.

- 플레이어가 잘못된 카드를 선택한 경우
- 게임에 사용할 수 있는 유효한 카드 후보가 부족한 경우

게임 종료 시 다음 정보를 표시한다.

- 최종 점수
- 최고 점수
- 마지막으로 비교한 카드
- 각 카드의 최초 출시일
- 다시 플레이하기

## 15. Best Score

MVP에서는 플레이어의 최고 점수를 브라우저에 저장한다.

별도의 회원가입이나 서버 저장은 사용하지 않는다.

새로운 게임이 종료되면 현재 점수가 기존 최고 점수보다 높은 경우 최고 점수를 갱신한다.

## 16. Game Restart

게임 종료 후 플레이어는 즉시 새로운 게임을 시작할 수 있다.

새 게임을 시작하면 다음 상태를 초기화한다.

- 현재 점수
- 현재 streak
- 사용된 카드 목록
- 현재 카드
- 다음 카드

최고 점수는 유지한다.

## 17. MVP Scope

### Included

- 두 장의 카드 비교
- 카드 최초 출시일 비교
- 카드 좌우 비교
- 랜덤 카드 선택
- 출시일 기반 난이도 조절
- 정답 / 오답 판정
- 점수
- streak
- Game Over
- Best Score
- Game Restart
- 모바일 대응

### Not Included

- 로그인 / 회원가입
- 서버 기반 랭킹
- 친구 대결
- 커뮤니티
- 댓글
- 카드 수집
- 덱 빌더
- 여러 게임 모드
- 사용자 카드 등록
- 난이도 선택 기능

## 18. Future Considerations

MVP 이후 다음 기능을 고려할 수 있다.

- Daily Challenge
- 공유용 결과 카드
- 글로벌 랭킹
- 플레이 통계
- 확장팩별 게임
- 특정 기간의 카드만 사용하는 게임
- 카드 출시 연도 맞히기
- 카드 비용 비교
- 공격력 / 생명력 비교
- 기타 카드 속성 기반 Higher or Lower 게임

이러한 기능은 MVP의 핵심 게임 규칙을 변경하지 않는 것을 원칙으로 한다.

## 19. Design Principles

### Simple

플레이어가 별도의 설명 없이도 게임 방법을 이해할 수 있어야 한다.

### Fast

한 라운드의 판단과 결과 확인이 빠르게 이루어져야 한다.

### Fair

각 라운드는 논리적으로 유일한 정답을 가져야 한다.

### Challenging

게임이 진행될수록 카드 간 출시일 차이가 좁아져 플레이어의 판단을 요구해야 한다.

### Replayable

게임마다 카드 조합이 달라지고, 높은 점수를 갱신하기 위해 반복 플레이할 수 있어야 한다.
